## Vulnerability Disclosure Policy

1. **Report**: Send detailed vulnerability description to adbd04@gmail.com with `[SECURITY]` prefix
2. **Acknowledge**: Receipt confirmation within 48 hours
3. **Assess**: Security team evaluates severity and impact
4. **Fix**: Patch developed and tested
5. **Disclose**: Coordinated disclosure after patch release

See [SECURITY.md](SECURITY.md) for full policy details.

## Communication Guidelines

### For Security Reports

Include in your security report:
- Description of the vulnerability
- Steps to reproduce
- Impact assessment
- Suggested fix (if available)
- Your contact information for follow-up

### For Bug Reports

Include:
- TweetNaCl-Modular version
- Platform/architecture
- Compiler and version
- Steps to reproduce
- Expected vs actual behavior

### For Feature Requests

Include:
- Use case description
- Proposed API design (if applicable)
- Security considerations
- Performance implications
